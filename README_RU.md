# Red Ball: три уровня, SDK-1.1M + FreeRTOS

Готовый проект STM32CubeIDE для STM32F407VGT6: платформер с прыжками, прокруткой мира, платформами, ямами, шипами, тремя звёздами на каждом уровне и финишным флагом. В игре три уровня с разным оформлением: зелёные холмы, опасный каньон и небесная башня. После третьего уровня появляется анимированный экран поздравления. Звёзды необязательны для перехода. Прыжки, звёзды, проигрыш, переходы и победа сопровождаются звуками через зуммер.

В презентации МК3 перечислены «Змейка» и «Тетрис». Red Ball сделан по вашему уточнению; обязательное использование FreeRTOS сохранено.

## Что уже установлено и скачано

STM32CubeIDE 1.19.0 и ARM GCC 13.3 уже были установлены на Mac. Официальные примеры скачаны в соседнюю папку `SDK-1.1M`. HAL, CMSIS-RTOS v1, FreeRTOS и шрифты включены в этот проект: дополнительно скачивать FreeRTOS не нужно. Исходный репозиторий: https://github.com/lmtspbru/SDK-1.1M. Его руководство `SDK1.1M.pdf` находится в папке репозитория.

## Запуск

Проект `RedBall_FreeRTOS` импортирован в рабочую область `workspace_1.19.0`. Выберите именно его в Project Explorer и нажмите значок молотка. При переносе: File → Open Projects from File System → выбрать папку проекта → Finish.

Независимая сборка из терминала:

```sh
cd "/Users/konstantinfadin/Desktop/itmo/third year/sys/SDK-1.1M/RedBall_FreeRTOS"
python3 build.py
```

Результат: `build/RedBall_FreeRTOS.elf`, `.hex`, `.bin`. IDE создаёт свою сборку в `Debug/`.

Подключите учебный стенд кабелем передачи данных к разъёму **USB DBG**, включите питание. Скрипт ниже записывает прошивку, проверяет запись и перезапускает микроконтроллер:

```sh
python3 flash.py
```

Используется встроенный FT2232 (VID:PID 0403:6010), JTAG 1 МГц. Для другого программатора или процессорного модуля конфигурацию нужно изменить. Windows-драйвер Zadig на macOS не нужен. Если OpenOCD сообщает, что FTDI не найден, проверьте USB DBG, кабель и питание.

## Управление

Ряды указаны сверху вниз, колонки слева направо. Числа соответствуют обычной телефонной раскладке; если надписи отличаются, ориентируйтесь на положение кнопок.

| Кнопка | Положение | Действие |
|---|---|---|
| 4 | 2-й ряд, слева | Влево |
| 6 | 2-й ряд, справа | Вправо |
| 2 | 1-й ряд, по центру | Прыжок; старт; повтор; следующий уровень |
| 5 | 2-й ряд, по центру | Пауза / продолжение |
| 0 | 4-й ряд, по центру | Выйти в главное меню из любого состояния |

Для нового прыжка отпустите и снова нажмите 2. Направление можно удерживать вместе с прыжком. HUD: `L` — уровень, `*` — собранные звёзды, `D` — количество смертей (три последних цифры).

## Как выполнены требования по FreeRTOS

- `InputTask`: сканирование клавиатуры через PCA9538, подавление дребезга, номинальный период 10 мс, очередь последнего состояния кнопок.
- `GameTask`: физика с фиксированным шагом 20 мс через `vTaskDelayUntil`, столкновения и состояния игры. Только эта задача изменяет игровой мир.
- `DisplayTask`: получает копию состояния через очередь длины 1 и рисует кадр. Старые кадры заменяются новыми, логика не ждёт дисплей.
- `SoundTask`: воспроизводит короткие игровые сигналы и победную мелодию через TIM2/PWM, не останавливая физику и дисплей.
- Мьютекс с наследованием приоритета защищает общую I²C1 от одновременного обращения клавиатуры и OLED. Только DisplayTask владеет буфером изображения.
- SysTick обслуживает FreeRTOS; TIM1 — время HAL. Включены проверки переполнения стека и отказа выделения памяти.

Дисплей: 128×64, адрес HAL 0x78. Клавиатура: PCA9538, адрес HAL 0xE2. I²C1: PB8/SCL, PB9/SDA, 100 кГц — как в рабочих примерах `SDK_Keyboard` и `SDK_RedBall`. Зуммер: TIM2_CH1, PA5. Ошибка запуска PWM отключает только звук и не может остановить FreeRTOS. MCU работает от внутреннего HSI 16 МГц, как в исходном примере FreeRTOS.

## Файлы

- `Core/Src/game.c`, `Core/Inc/game.h`: независимая от платы физика, карты трёх уровней и состояния.
- `Core/Src/game_render.c`: пиксельная графика и интерфейс.
- `Core/Src/freertos.c`: четыре задачи, очереди, мьютекс, сканирование клавиатуры и звуковые события.
- `Core/Src/buzzer.c`, `Core/Src/tim.c`: генерация звуков и мелодии через PWM.
- `Core/Src/i2c.c`, `oled.c`, `fonts.c`: драйверы и шрифты на основе учебных примеров.
- `SDK11M.cfg`, `flash.py`: прошивка встроенным программатором.
- `preview/gameplay.gif`: прохождение трёх уровней, отрисованное настоящим C-кодом игры на компьютере. Это не запись работы платы.
- `tests/`: проверки физики и поиск маршрутов с тремя звёздами.

Оригинальный `.ioc` и старая Windows-конфигурация отладки сохранены в `reference/` **только для справки**. Они описывают исходный пример, а не игру. Не запускайте по ним Generate Code: это заменит пользовательскую RTOS-конфигурацию. Для сборки текущего проекта генерация CubeMX не нужна.

## Проверки и ограничения

Сборка в STM32CubeIDE завершилась с 0 errors, 0 warnings. Повтор тестов на Mac: `python3 tests/run.py`.

Проверены сборка ARM-прошивки, движение, прыжок, пауза, возврат в меню, падение, шипы, повтор, сбор звёзд, переходы между тремя уровнями и победа. Автоматический поиск нашёл прохождение каждого уровня со всеми тремя звёздами. Изображения проверены через C-отрисовщик с заменой OLED на буфер в памяти.

Запуск на физической плате и электрическая работа I²C не проверены. При другой ревизии стенда может потребоваться адаптация распиновки или раскладки клавиатуры. В отладчике доступны счётчики `redball_keyboard_errors`, `redball_oled_errors`.
